# Playbook: Mature existing-harness adoption

Use this instead of a blind root overlay when existing harness material is present.

1. **Freeze originals:** treat existing instructions, roles, rules, decisions, knowledge, pending work, and verification sources as read-only. Record the discovery snapshot revision, time, selector expansions, and identities.
2. **Inventory:** inspect root collisions, path-scoped rules, role systems, narrative decisions, learning references, verification sources, generated worktrees/builds, and secret-bearing paths. Do not read or copy secret values.
3. **Classify everything:** assign every discovered material item one of the four migration classifications. Silent omission is prohibited.
4. **Namespace:** place the kit and adoption state where they cannot overwrite existing root authorities. Do not assume kit-root ownership.
5. **Add provenance:** every migrated/retained/duplicated/unresolved item records source identity, destination, and reciprocal backlink.
6. **Record coexistence:** define authority, path-rule precedence, role bindings, knowledge/pending-work ownership, exclusions, and conflict escalation.
7. **Validate structural coverage:** run host-integration validation. Refresh discovery if selector expansion or content identity drifted.
8. **Obtain semantic sign-off:** the project owner and an existing-harness maintainer compare material item-by-item. Machine coverage is insufficient.
9. **Approve context separately:** only a current snapshot can reach human approval and seed a graph.
10. **Authorize cutover separately:** preserve originals and intentional duplicates until a human approves semantic equivalence and then explicitly authorizes cutover/deletion.

Installing `core-learning` during adoption does not activate learning. Consent, retention, observation, and publication remain disabled until separately approved in the learning profile.
