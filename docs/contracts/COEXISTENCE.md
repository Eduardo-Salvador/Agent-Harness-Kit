# Contract: Existing-harness coexistence and precedence

Use this contract when a host already has root instructions, role systems, path-scoped rules, knowledge stores, pending-work authorities, or platform-specific behavior.

## Required precedence record

An instance must name:

- existing root instruction files and their authority;
- Agent Harness Kit's namespaced location and neutral entry point;
- path-scoped rules that override general instructions in their scope;
- existing role bindings to neutral responsibilities without rewriting the originals;
- authoritative knowledge/decision/pending-work sources during coexistence;
- generated/excluded paths such as platform worktrees;
- secret-bearing paths that may be inventoried by name/identity but whose values cannot be migrated;
- conflict escalation and the human authority for semantic/cutover decisions.

## Precedence rules

1. Existing authorities remain authoritative unless an approved decision explicitly changes them.
2. More-specific path rules apply within their scope; the neutral layer records but does not erase them.
3. Namespaced kit artifacts add coordination and evidence. They cannot silently replace existing root files or pending-work sources.
4. Conflicts block affected work and create a decision; recency alone does not choose authority.
5. Packaging selection never grants learning consent, retention, observation, or publication authority.
6. Originals and intentional duplicates remain until structural coverage, human semantic-equivalence review, and separate cutover authorization all pass.
